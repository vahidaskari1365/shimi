# شیمی‌یار — دستیار هوشمند فرمولاسیون شوینده و آرایشی-بهداشتی (MVP)

نمونهٔ اولیهٔ تولیدگرا (Production-Oriented MVP) یک دستیار دانشی مبتنی بر RAG برای پژوهش، توسعه، پشتیبانی فرمولاسیون و عیب‌یابی محصولات شوینده، آرایشی و بهداشتی.

> **هشدار:** این یک ابزار پژوهشی است. پاسخ‌ها به اسناد استناد می‌شوند اما تضمین‌شده نیستند و جایگزین شیمی‌دان مجرب، آزمایشگاه، بازبینی ایمنی و مقرراتی نیستند. سیستم هرگز نتایج آزمایش یا خواص شیمیایی را از خودش نمی‌سازد.

---

## قابلیت‌ها

| بخش | توضیح |
|---|---|
| **گفت‌وگوی مستندمحور** | پاسخ فقط از مدارک بازیابی‌شده، با استناد `[n]` به سند و صفحه، تفکیک «پاسخ مستند» از «فرضیهٔ نیازمند تأیید» و رفتار صریحِ «مدارک کافی نیست» |
| **بازیابی ترکیبی (Hybrid RAG)** | BM25 کلیدواژه‌ای + بردار معنایی (کسینوس) + ادغام **Reciprocal Rank Fusion**؛ هر جزء برای ارزیابی قابل خاموش‌کردن است |
| **نمایه‌سازی اسناد** | PDF (صفحه‌به‌صفحه با unpdf)، TXT، Markdown و CSV (جدول‌ها به‌صورت صفحه‌های شبه‌جدول ارجاع‌پذیر)؛ قطعه‌بندی با اندازه/هم‌پوشانی قابل‌تنظیم؛ تشخیص PDF اسکن‌شده (نیازمند OCR)؛ dedupe با SHA-256؛ بازنمایه‌سازی و حذف کامل |
| **گراف دانش** | ۸ نوع موجودیت و ۷ نوع رابطهٔ تایپ‌دار؛ استخراج با LLM از اسناد (همیشه با برچسب «نیازمند راستی‌آزمایی» + منشأ + سطح اطمینان)؛ ثبت دستی (تأییدشده)؛ پیمایش BFS چند-پله‌ای؛ نمای شبکه‌ای SVG |
| **پایگاه فرمولاسیون** | مواد اولیه، فرمول‌های **نسخه‌دار**، درصدها با واحد صریح و اعتبارسنجی مجموع ۱۰۰٪، اندازه‌گیری‌ها با واحد، آزمایش‌ها |
| **عیب‌یابی محتاطانه** | ثبت علائم/شرایط/اندازه‌گیری‌ها → بازیابی مدارک → «عوامل احتمالی مبتنی بر شواهد» با سطح اطمینان + اطلاعات موردنیاز + اقدامات بررسی — بدون علت قطعی و بدون دستور تغییر فرمول |
| **API مستند** | ۱۹ مسیر REST با اعتبارسنجی Zod، کدهای خطای یکنواخت و حسابرسی |
| **رابط فارسی RTL** | طراحی تیرهٔ آزمایشگاهی، موشن گرافی (framer-motion)، ریسپانسیو، پانویس چسبان |

## راه‌اندازی

```bash
# ۱) نصب وابستگی‌ها
bun install

# ۲) متغیرهای محیطی (کپی از نمونه)
cp .env.example .env

# ۳) همگام‌سازی پایگاه‌داده
bun run db:push

# ۴) اجرا (پورت ۳۰۰۰)
bun run dev
```

سپس در تب **تنظیمات** دکمهٔ «بارگذاری دادهٔ نمایشی مصنوعی» را بزنید تا ۳ سند نمونهٔ فارسی، ۱۰ ماده، ۲ فرمولاسیون، گراف و یک پروندهٔ عیب‌یابی تحلیل‌شده ساخته شود (همه برچسب `[نمونهٔ مصنوعی]`).

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `DATABASE_URL` | `file:./db/custom.db` | مسیر SQLite (Prisma) |
| `CHUNK_SIZE` | `900` | اندازهٔ قطعه (نویسه) |
| `CHUNK_OVERLAP` | `150` | هم‌پوشانی قطعات |
| `RETRIEVAL_TOP_K` | `8` | تعداد شواهد بازیابی‌شده |
| `RRF_K` | `60` | ثابت Reciprocal Rank Fusion |
| `EMBEDDING_DIM` | `384` | بعد بردار نهفته |
| `MAX_UPLOAD_MB` | `15` | حداکثر حجم آپلود |
| `LLM_MODEL` | `z-ai-default` | نام مدل (نمایشی) |
| `LLM_PROVIDER` | `z-ai-web-dev-sdk` | ارائه‌دهندهٔ مدل زبانی |
| `GRAPH_EXTRACT_MAX_CHUNKS` | `24` | سقف قطعات ورودی استخراج گراف |

## معماری (خلاصه)

```
Upload (PDF/TXT/MD/CSV)
   │  extract(unpdf/papaparse) → pages → chunk(size/overlap) → embedding(۳۸۴بعدی، آفلاین)
   ▼
SQLite/Prisma ── Document ── Chunk(text, page, heading, vector)
   │                                │
   │              BM25 کلیدواژه ─┤─ کسینوس برداری
   │                        RRF Fusion → top-K شواهد
   │                                     │
GraphEntity/GraphRelationship ◄─ LLM   LLM پاسخ + استناد [n]
(همسایگی SQLite، BFS چند-پله)         «شواهد» ≠ «فرضیه»
```

**نقاط تعویض‌پذیری (Adapter Interfaces):** `EmbeddingProvider` (src/lib/retrieval/embeddings.ts)، `llmComplete` (src/lib/llm/provider.ts) و `retrieveHybrid` طوری طراحی شده‌اند که ارائه‌دهندهٔ مدل، مدل بردارسازی (مثلاً Ollama با nomic-embed-text) یا فروشگاه بردار (pgvector) بدون بازنویسی برنامه عوض شوند.

## گزارش ارزیابی بازیابی (پیکرهٔ مصنوعی کوچک)

۱۵۰۰ قطعهٔ ساده نه — پیکره: ۴ سند نمایشی؛ ۱۰ پرسش آزمون با سند مرتبطِ مشخص:

| روش | Recall@5 | MRR |
|---|---|---|
| کلیدواژه (BM25) | ۸۰٪ (۸/۱۰) | 0.75 |
| برداری | ۹۰٪ (۹/۱۰) | 0.78 |
| **ترکیبی (RRF)** | **۹۰٪ (۹/۱۰)** | **0.83** |

- ادغام RRF، MRR را نسبت به هر دو روش تنها بهتر کرد (رتبهٔ اولِ دقیق‌تر).
- ۱ مورد miss مربوط به سندی است که پیش از اجرای ارزیابی حذف شده بود (پرسش آزمونش باقی مانده بود).
- این پیکرهٔ آزمون کوچک و مصنوعی است و ادعای تعمیم‌پذیری ندارد؛ برای ارزیابی واقعی، پیکرهٔ داخلی شرکت لازم است.

## محدودیت‌های شناخته‌شده (صادقانه)

1. **SQLite به‌جای PostgreSQL/pgvector** — محیط اجرا فقط SQLite دارد. برای مقیاس بزرگ‌تر، مهاجرت به Postgres + pgvector + FTS لازم است؛ لایهٔ بازیابی برای این تعویض آماده است.
2. **بردارساز آفلاین hashing-TFIDF** (۳۸۴بعدی، ۳-گرام نویسه‌ای) — کیفیت معنایی واقعی مدل‌های embedding را ندارد؛ برای فارسی کارآمد است اما جای ارتقا با `EmbeddingProvider` است.
3. **OCR پیاده نشده** — PDFهای اسکن‌شده شناسایی و با وضعیت `needs_ocr` گزارش می‌شوند ولی OCR اجرا نمی‌شود.
4. **احراز هویت ندارد** — فقط در محیط محلی/داخلی اجرا شود؛ مرز امنیتی در تب تنظیمات مستند است.
5. **استخراج جدول در PDF** — جدول‌ها به‌صورت متن هم‌تراز حفظ می‌شوند (نه ساختار جدولی دقیق). CSV ساختار کامل دارد.
6. **کوالیتید آزمون خودکار (pytest/unit)** — طبق خط‌مشی محیط توسعه این repo، suite تست نوشته نشده؛ به‌جای آن راستی‌آزمایی E2E مرورگری + ارزیابی Recall/MRR انجام شد. برای تولید، نوشتن suite تست لازم است.
7. **Docker/Alembic** — در این محیط قابل اجرا نیست؛ Prisma `db push` جایگزین migration است و Dockerfile/Compose باید در استقرار واقعی اضافه شود.
8. **نما و متن LLM** — کیفیت پاسخ به مدل پشت `llmComplete` بستگی دارد؛ خروجی JSON با تحمل خطا parse می‌شود و در خرابی، پاسخ خامِ بدون ادعای ساختار ذخیره/نمایش می‌شود.

## امنیت و محرمانگی

- فایل‌ها خارج از `public/` با نام UUID ذخیره می‌شوند؛ نام اصلی فقط در DB.
- اعتبارسنجی پسوند/حجم؛ مسیر ذخیره ساخته‌شده از UUID (بدون ورودی کاربر در مسیر) → مقاوم به path traversal.
- کوئری‌ها همه پارامتری (Prisma) → مقاوم به SQL Injection.
- حسابرسی رویدادها (create/delete/reindex/seed) بدون لاگ محتوای اسناد.
- `robots: noindex/nofollow`؛ فرض: اسناد محرمانهٔ شرکت.
- قبل از اتصال هر ارائه‌دهندهٔ خارجی LLM، سیاست دادهٔ محرمانه باید صریحاً تأیید شود.

## گام‌های بعدی برای تولید

1. مهاجرت به PostgreSQL + pgvector + FTS5 و suite تست خودکار (pytest/CI).
2. اتصال مدل embedding واقعی (Ollama محلی یا سرویس داخلی تأییدشده) و باز-ارزیابی فارسی.
3. احراز هویت (SSO/LDAP سازمانی) + نقش‌ها + تفکیک دسترسی به اسناد.
4. Dockerfile + Compose + migration رسمی (Alembic/Prisma migrate) + پشتیبان‌گیری.
5. ارزیابی منظم با پیکرهٔ واقعی و پایش کیفیت استناد.
