# گزارش ارزیابی ۶ مخزن متن‌باز — دستیار پژوهشی فرمولاسیون (AI Formulation Assistant)

**Task ID:** `2-a` · **عامل:** general-purpose (repo evaluator) · **نوع کار:** فقط تحقیق/ارزیابی — هیچ کدی در `src/` یا فایل‌های برنامه نوشته نشد و هیچ مخزنی داخل پروژه clone نشد (بررسی‌ها فقط از طریق `raw.githubusercontent.com` و یک کلون سطحی در `/tmp` بود که پس از مطالعه حذف شد).

**زمینه فنی محصول (بررسی‌شده از `package.json` خود پروژه):** Next.js `16.1.1` + React `19` + TypeScript `5` + Prisma `6` (SQLite) + Zod `4` + SDK داخلی `z-ai-web-dev-sdk`. هر پیشنهادی که با این استک سازگار نباشد، صریحاً «غیرقابل‌ادغام مستقیم» علامت خورده است.

**محدودیت‌های این بررسی (صادقانه):**
- GitHub REST API برای این IP محدود شده بود (403 rate-limit)؛ بنابراین آمار star/fork/آخرین push از API گرفته نشد. مبنای ارزیابی: README و LICENSE هر ۶ مخزن (fetch مستقیم، همگی موفق) + یک کلون سطحی از مخزن mnfst در `/tmp` برای یافتن فایل مجوز.
- اعداد تبلیغاتی (مثلاً «۳۷۵ ارائه‌دهنده» در OmniRoute یا «~۱.۶۲B توکن/ماه») ادعای خود مستندات پروژه‌هاست و مستقل راستی‌آزمایی نشد.
- هر ۶ مخزن در دسترس بودند؛ هیچ‌کدام 404 یا خصوصی نبود.

## بررسی تفصیلی هر مخزن

### 1) OmniRoute — `diegosouzapw/OmniRoute`

- **کاربرد:** درگاه (gateway) محلی و open-source برای مدل‌های AI؛ یک endpoint یکپارچه سازگار با OpenAI در `http://localhost:20128/v1` با فالبک ۴ لایه (Subscription → API Key → Cheap → Free)، فشرده‌سازی توکن (ادعای ۱۵–۹۵٪)، داشبورد، حالت `serve --headless`، MCP/A2A و کاتالوگ free-tierها (ادعای ۳۷۵ ارائه‌دهنده/۱۵۰+ free). مدل کاربردی اصلی آن اتصال ابزارهای کدنویسی (Claude Code، Cursor، Cline و…) به مدل‌های رایگان/ارزان است.
- **مجوز:** MIT (فایل `LICENSE`، `Copyright (c) 2026 diegosouzapw`) — قابل استفاده تجاری.
- **نصب:** `npm install -g omniroute` یا `docker run … diegosouzapw/omniroute` (AMD64+ARM64) یا `npx -y omniroute` یا از سورس. Node `>=22.22.2 <23 || >=24`.
- **وابستگی‌ها:** استک: TypeScript کامل، Next.js 16 + React 19، better-sqlite3 (WAL)، Zod 4 — نکته جالب: تقریباً همان استک پروژه ما. اما دپ‌های native سنگین دارد: `keytar`, `onnxruntime-node`, `@parcel/watcher`, `@swc/core`, `protobufjs`, `esbuild` و `postinstall` اجباری (npm باید با `--allow-scripts` اجرا شود).
- **محدودیت‌های استقرار:** یک **فرایند جانبی مستقل** (سرویس + پورت 20128) است، نه کتابخانه npm قابل import در اپ Next.js ما. نیاز به «Bring Your Own Provider» دارد (حساب/API key ارائه‌دهنده‌ها). در محیط سندباکس تک‌فرایندی فعلی، اجرای یک sidecar دائمی ارزش افزوده‌ای برای MVP ندارد.
- **ریسک‌های امنیتی:** (۱) قابلیت شفاف‌سازی TLS با **نصب CA در trust store سیستم** (MITM/TPROXY) — در صورت فعال‌شدن ریسک بالایی برای هر ماشینی که روی آن اجرا شود؛ (۲) اجرای اسکریپت‌های postinstall و تولید فایل `.env` محلی هنگام نصب (ریسک supply-chain)؛ (۳) ارائه‌دهنده‌های free-tier با شرایط سرویس ضعیف — خود کاتالوگ ۱۲ ارائه‌دهنده را `tos: avoid` علامت زده؛ (۴) لینک‌های affiliate متعدد در README (نشانه انگیزه تجاری در توزیع). در مقابل: local-first، رمزنگاری کلیدها AES-256-GCM، telemetry خاموش به‌صورت پیش‌فرض.
- **تصمیم نهایی: فقط-مرجع / اختیاری.** طبق قاعده کاربر فقط به‌عنوان درگاه اختیاری مدل‌ها ارزیابی شد. چون محصول با `z-ai-web-dev-sdk` کار می‌کند، الان نیازی به آن نیست؛ اگر در آینده ویژگی «انتخاب مدل توسط کاربر (BYOK)» ساخته شود، OmniRoute (به دلیل پروتکل سازگار OpenAI و مجوز MIT) گزینه‌ای مستند برای معرفی به کاربران قدرتمند است — ولی حتی آن‌جا هم ادغام درون‌برنامه‌ای نیست، بلکه معرفی/اجرا به‌صورت ابزار جانبی است.

### 2) awesome-free-llm-apis — `mnfst/awesome-free-llm-apis`

- **کاربرد:** یک **فهرست کیوریت‌شده (awesome list)** از APIهای LLM با free tier «دائمی» برای inference متنی. ساختار: `data.json` (۱۶ ارائه‌دهنده) → تولید خودکار README با CI؛ هر ادعا با `sources.json` و پوشه `.verify` مستند و ارجاع‌دار است (نقطه قوت واقعی این ریپو). یک اسکیل ایجنت هم داخلش هست (`free-llm-apis/SKILL.md`) برای راهنمای گرفتن کلید رایگان. ارائه‌دهندگان: Cohere، Gemini، Mistral، Z AI (GLM-Flash)، Groq، Cloudflare Workers AI، NVIDIA NIM، OpenRouter، OVHcloud و… همراه با جدول دقیق rate-limit و پانوشت‌های حریم خصوصی (مثلاً استفاده از promptهای free-tier برای آموزش مدل).
- **مجوز:** **CC0 1.0 Universal** (مالکیت عمومی). نکته: فایل با نام `license` (حروف کوچک) است، نه `LICENSE` — به همین دلیل در اسکن اولیه با نام‌های مرسوم یافت نشد و با کلون سطحی در `/tmp` شناسایی شد.
- **نصب:** ندارد و لازم هم ندارد — صرفاً داده/مستند است؛ مصرف اطلاعات از README یا `data.json`.
- **وابستگی‌ها:** هیچ وابستگی اجرایی؛ فقط اسکریپت‌های Node اختیاری برای اعتبارسنجی/تولید داده (`generate-readme.js` و…).
- **محدودیت‌های استقرار:** سرویس API مستقل **نیست** (طبق قاعده کاربر). داده‌ها تاریخ‌دار و متغیرند؛ برخی ارائه‌دهنده‌ها احراز هویت هویتی چین می‌خواهند (ModelScope، SiliconFlow) یا از خارج از چین قابل تست نیستند؛ چند free-tier اجازه لاگ/آموزش روی prompt می‌دهند — برای داده فرمولاسیون بالقوه محرمانه مرتبط نیست.
- **ریسک‌های امنیتی:** پایین (فقط مصرف اطلاعاتی). ریسک اصلی اطلاعاتی است: اتکا به محدودیت‌های free-tier بدون تاریخ انقضا؛ پانوشت‌های خود ریپو این را صادقانه هشدار می‌دهد.
- **تصمیم نهایی: فقط-مرجع.** به‌عنوان کاتالوگ مرجع برای تصمیم‌گیری درباره ارائه‌دهندگان رایگان (مخصوصاً GLM-Flash سازگار با اکوسیستم Z AI) نگه داشته می‌شود؛ هیچ وابستگی یا کدی از آن به پروژه اضافه نمی‌شود.

### 3) Agent-Reach — `Panniantong/Agent-Reach`

- **کاربرد:** ابزار CLI (عمدتاً چینی‌زبان) که به ایجنت‌ها دسترسی «فقط-خواندنی» به پلتفرم‌هایی می‌دهد که معمولاً از دستشان خارج است: پشت لاگین (Xiaohongshu، Reddit، LinkedIn…)، پلتفرم‌های چینی (bilibili، V2EX، Xueqiu)، زیرنویس/تبدیل گفتار YouTube و جست‌وجوی وب. معماری: هر پلتفرم = لیست ترتیبی ابزار اولویت‌دار + fallback.
- **مجوز:** MIT (`Copyright (c) 2025 Agent Eyes`).
- **نصب:** غیرمتعارف — نصب با سپردن یک URL (`docs/install.md`) به خود ایجنت تا دستورالعمل‌ها را بخواند و اجرا کند (ابزار `uv` را هم خودش نصب می‌کند). هشدار صریح README: پکیج PyPI به نام `agent-reach` **این پروژه نیست** (namesquatting).
- **وابستگی‌ها:** Python 3.10+، `uv`، ابزارهای CLI هر کانال (bili-cli، yt-dlp، Jina Reader، Exa)، مرورگر اختصاصی برای کانال‌های لاگین‌دار، کلید Groq/OpenAI برای تبدیل گفتار به متن.
- **محدودیت‌های استقرار:** ابزار دسکتاپ/CLI است؛ در اپ Next.js سمت سرور قابل embed نیست (پایتون + مرورگر + session). کانال‌های آن (سرگرمی/شبکه اجتماعی چینی/بورس) با دامنه «فرمولاسیون شوینده/آرایشی» بی‌ارتباط‌اند؛ برای وب پژوهشی عمومی هم SDK داخلی همین محیط جست‌وجوی وب دارد.
- **ریسک‌های امنیتی:** (۱) **کپی session/کوکی لاگین کاربر از Chrome** به مرورگر اختصاصی خودش — حتی با توضیحات خوب پروژه، ریسک حریم خصوصی و بن‌شدن اکانت واقعی است؛ (۲) مدل نصب «fetch دستورالعمل از URL و اجرا» دقیقاً الگوی ریسک prompt-injection / supply-chain است؛ (۳) نقض احتمالی ToS پلتفرم‌ها؛ (۴) هشدار رسمی خود پروژه درباره پکیج جعلی PyPI.
- **تصمیم نهایی: ردشده (فعلاً).** طبق قاعده کاربر فقط در صورت «نیاز به جمع‌آوری اطلاعات عمومی از وب» اضافه می‌شد؛ چنین نیازی برای این محصول تعریف نشده و حتی اگر شود، این ابزار به دلیل معماری Python/دسکتاپی برای استک ما مناسب نیست. شرط بازنگری: اگر نیازی مستند به منابع خاص (ویدیو/پلتفرم‌های لاگین‌دار) تعریف شود، دوباره ارزیابی می‌شود.

### 4) ECC — `affaan-m/ECC`

- **کاربرد:** «هارنس سیستم‌عامل ایجنت» برای توسعه نرم‌افزار با AI: چرخه `plan → test → implement → review → verify → remember → improve` شامل ۷۱ ایجنت تخصصی (planner، code-reviewer، security-reviewer، tdd-guide، e2e-runner…)، ۳۱۱ اسکیل، ۹۷ کامند، hooks و حافظه/یادگیری مستمر، و ابزار **AgentShield** برای اسکن امنیتی پرامپت‌ها/hooks/MCP/secrets.
- **مجوز:** MIT برای خود ریپو (OSS «برای همیشه» به ادعای README)؛ اما **ECC Pro** (GitHub App هاست‌شده برای ریپوهای خصوصی) تجاری است (از ~$19/seat/ماه) — مدل open-core.
- **نصب:** `npx ecc-universal@2.2.3 setup` (نیازمند Node ≥18، Git، و Claude Code ≥2.1 برای مسیر پلاگین) یا پلاگین native: `/plugin marketplace add https://github.com/affaan-m/ECC` و `/plugin install ecc@ecc`. مسیرهای native برای Codex و Qoder هم دارد. قاعده مهم مستندات: «فقط یک مسیر نصب در هر هارنس» (نصب تودرتو باعث تکرار می‌شود).
- **وابستگی‌ها:** Node 18+؛ برخی قابلیت‌ها (یادگیری مستمر، GAN، orchestration) به Bash/Python وابسته‌اند. سازگاری کامل فقط با Claude Code؛ Cursor/OpenCode بتا؛ بقیه آزمایشی.
- **محدودیت‌های استقرار:** بسیار سنگین از نظر context (تبلیغ ۳۱۱ اسکیل/۷۱ ایجنت) و مخصوص هارنس‌های کدنویسی — نه وابستگی محصول. در این سندباکس (که خودش سیستم skills/agent مجزا دارد) نصب کامل آن نه تضمین‌شده است و نه مطلوب؛ باگ‌های شناخته‌شده ویندوز native هم در مستندات ذکر شده.
- **ریسک‌های امنیتی:** (۱) hooks در زمان SessionStart کد shell اجرا می‌کنند — سطح حمله واقعی؛ (۲) هشدار رسمی خود پروژه: نصب فقط از کانال‌های رسمی (ریسک mirror/آپلود مخرب شخص ثالث)؛ (۳) سطح context بالا می‌تواند رفتار ایجنت را نامطمئن‌تر کند.
- **تصمیم نهایی: فقط-مرجع.** نصب کامل رد می‌شود؛ ایده‌های انتخابی آن (چرخه TDD، ایجنت security-reviewer، الگوی AgentShield برای اسکن skills/hooks، memory vault بین-هارنسی) به‌عنوان مرجع طراحی فرایند توسعه/تست ما ثبت می‌شود.

### 5) skills — `mattpocock/skills`

- **کاربرد:** مجموعه‌ای کوچک و ترکیب‌شدنی از اسکیل‌های markdown «مهندسی واقعی» برای ایجنت‌های کدنویسی، برخلاف فریم‌ورک‌های فرایند-مالک (GSD/BMAD/Spec-Kit). اسکیل‌های کلیدی: `/grill-me` و `/grill-with-docs` (هم‌راستاسازی با پرسشگری + ساخت GLOSSARY/ADR)، `/tdd` (چرخه قرمز-سبز-بازآرایی)، `/code-review` (دو-محوره: استانداردها + وفاداری به spec، با ساب‌ایجنت موازی)، `/diagnosing-bugs`، `/to-spec`، `/implement`، `/retro`، `/handoff`، `/wayfinder`.
- **مجوز:** MIT (`Copyright (c) 2026 Matt Pocock`).
- **نصب:** `claude plugin install mattpocock-skills@claude-plugins-official` یا برای سایر ایجنت‌ها `npx skills@latest add mattpocock/skills -a <agent>` یا نسخه فایل‌به‌فایل از skills.sh؛ سپس یک‌بار `/setup-matt-pocock-skills` در هر ریپو.
- **وابستگی‌ها:** **هیچ وابستگی runtime** — فقط فایل‌های `SKILL.md` (متن دستورالعمل)؛ فقط به هارنسی نیاز دارد که skills را پشتیبانی کند.
- **محدودیت‌های استقرار:** مخصوص فرایند توسعه است، نه بخشی از محصول نهایی. در این محیط، مسیر واقع‌بینانه adoption، **کپی انتخابی چند اسکیل** (با نگهداشت attribution طبق MIT) به پوشه skills/ پروژه یا استفاده به‌عنوان مرجع است، نه نصب پلاگین کامل.
- **ریسک‌های امنیتی:** بسیار پایین — بدون کد اجرایی؛ تنها ریسک، «دستورالعمل» است که ایجنت را راهنمایی می‌کند؛ توصیه: بازبینی سریع محتوای هر SKILL.md قبل از استفاده (قاعده کلی: بدون اعتماد کورکورانه).
- **تصمیم نهایی: منتخب (انتخابی) برای بهبود فرایند توسعه و تست.** چون سبک، بدون وابستگی، MIT و مستقیماً معطوف به مشکلات واقعی (عدم هم‌راستایی نیاز، نبود حلقه بازخورد/تست، نرم‌افزار لج‌شده) است. کاندیداهای مشخص برای adoption: `tdd`، `code-review`، `grill-with-docs`، `diagnosing-bugs`، `handoff`. اجرای ادغام واقعی با عامل اصلی است.

### 6) ai-engineering-hub — `patchy631/ai-engineering-hub`

- **کاربرد:** آرشیو آموزشی ۹۳+ پروژه «production-ready» (بیشتر Python): RAG پایه (LlamaIndex/Ollama)، Agentic RAG با web-fallback، Corrective RAG (Firecrawl)، Trustworthy RAG (TLM)، RAG-SQL Router، ارزیابی/observability با Opik، MCP server/clientها، fine-tuning با Unsloth و…
- **مجوز:** MIT (`Copyright (c) 2024 patchy631`).
- **نصب:** نصب یکپارچه ندارد؛ هر پوشه یک پروژه مستقل با requirements خودش (pip).
- **وابستگی‌ها:** اکوسیستم Python — LlamaIndex، CrewAI، AutoGen، Qdrant/Milvus، Streamlit، سرویس‌های SaaS شخص ثالث (Firecrawl، BrightData، AssemblyAI، Groq و…). برخی پروژه‌ها کلید سرویس تجاری می‌خواهند.

- **تصمیم نهایی: فقط-مرجع.** برای مطالعه الگوهای RAG/مهندسی LLM مفید است؛ هیچ کد پایتونی از آن به محصول نمی‌رود. الگوهای منتخب برای بازطراحی TS (پیشنهاد مطالعه): `agentic_rag`، `trustworthy-rag`، `rag-sql-router`، `eval-and-observability`.
